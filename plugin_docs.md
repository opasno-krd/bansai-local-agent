1. Концепция «Everything is a Plugin»
	• Архитектура ядра Cordis: модели, инструменты (tools), UI и сессии равноправны, расширяются через apply(ctx) и автоматически изолируют эффекты (эффекты «откатываются» при выгрузке).
2. Формат Манифеста (Два типа)
	• Манифест бандла плагина (package.json): Объявляет поле "dsh": { "bundle": { "patch": "./cordis.patch.yml" } }}. Указаны жесткие требования по peerDependencies к @deepseek-ai/cordis.
	• Формат патча (cordis.patch.yml): Структурированная YAML-инструкция для регистрации строк плагинов (rows) в рантайме с использованием уникальных id.
3. Регистрация инструментов (Tools)
	• Пример экспорта провайдера, внедрение зависимости cmdlineArgs для кастомных аргументов командной строки через @deepseek-ai/dsh-cmdline.
	• Шаблон динамической оценки конфигов на базе JS-контекста (!!js ctx.myStartup...).
4. Полный пример готового плагина (TypeScript / ESM)
	• Пример файла index.js, экспортирующего имя, зависимости (inject) и метод инициализации apply(ctx).
5. Специфика Creator Mode (Режим инспекции)
	• Разбор 4-х режимов работы DSH (Standard, Code, Minimal, Creator).
	• Функции Creator Mode: динамическая отладка плагинов в памяти без изменения постоянных профилей и утилиты инспекции дерева Cordis хост-раннера.
6. Критерии валидации и «подводные камни» (Из-за чего падает рантайм)
	• Изоляция окружений: запрет Node-импортов в клиентской (браузерной) части.
	• Отказ от unscoped cordis в пользу @deepseek-ai/cordis.
	• Обязательное наличие prepare скриптов компиляции (например, через tsdown) для бесшовной установки плагинов напрямую из GitHub.

💡 Мои рекомендации для исключения повторных сбоев:

1. Не используйте глобальный cordis: Самая частая причина падения плагина на этапе монтирования (ошибка guaranteed runtime crash) — это использование в package.json обычной зависимости cordis вместо жестко зафиксированной @deepseek-ai/cordis от DeepSeek.
2. Разделение Host/Client: Если вы пишете плагин, добавляющий UI-карточки или панели настроек в веб-интерфейс, помните о дуальной архитектуре. Код, попадающий в клиентский бандл, не должен содержать импортов модулей Node.js (fs, path и т.д.).
3. Установка для тестов: При отладке тестируйте плагин, добавляя его в профиль командой dsh plugin --profile <имя_профиля> add ./hello-plugin. Для проверки корректности слоев всегда прогоняйте dsh --profile <имя> --dump-config — эта команда покажет, правильно ли встал ваш патч и не конфликтует ли его id с dsh-base. Утилиту валидации можно посмотреть в публичном репозитории организации omdsh-dev/dsh-plugin-check.
